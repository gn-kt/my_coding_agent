# intent：my_coding_agent Phase 3+ 想法#8——会话 fork L0：只读观测者

- 问题：会话是单进程独占的——想旁观一场正在跑的会话（复盘现场/面试演示），只能凑同一终端或事后翻 jsonl。想法 #8 定稿 L0：第二个进程**只读旁观**，新珠入树实时上屏，**写不进一个字**（fork 分支协作=L1、实时合写=L2 已否决）。
- 用户/场景：A 进程原三路径（one-shot/-i/--resume）零改动继续干活；B 进程 `--watch <id>` 挂上同一会话——先重建现场，再跟随新珠刷新；全程只读零 token。
- 输入 → 输出：
  - 输入：`npm run dev -- --watch <sessionId>`（读 sessions/ 下对应 jsonl）
  - 输出：先打**现场快照**（活跃路径投影 + 状态标记），后持续上屏新落盘的珠（类型/内容）；B 无任何写通道、无任何 LLM 调用
- 该拦什么（反例）：
  1. 观测者对树零写入——不追加不改不删（事实靠追加，观测者连进都不进）
  2. sessionId 不存在 → fail-loud 报错 exit 1，不静默空屏
  3. 半行写入不崩——A 正在写、B 读到不完整 JSON → 留待下轮，不 crash；但**中间行**坏 JSON = 真损坏，fail-loud 不静默吞
  4. 零 token——画面全靠读树重算投影，不发任何请求
  5. 文件变短/被重写 → fail-loud（观测者只懂追加）
- 该放什么（正常场景）：挂上 → 现场快照 → A 每落一颗珠，B 数秒内上屏
- 验收标准（5 条，每条可验证）：
  1. 双进程实测：A 落新珠，B 数秒内出现该珠内容（人工验证）
  2. 只读硬保证：B 运行期间 jsonl 只由 A 追加；B 代码零写调用（审 diff）
  3. 现场重建：挂上先打活跃路径投影快照（= resume 三动作只读版：翻树→摸线→标状态，判据用 repl.detectBranch 同一把刀），不惊动 A
  4. 半行容错：尾行不完整不崩、下轮补上；中间行损坏 fail-loud（单测）
  5. 回归：44+新 单测全绿；不存在 id → 明确报错 exit 1
- 范围外（明码标价）：L1 fork 分支 + 会话 PR 汇合｜L2 同线程实时合写（已否决）｜fs.watch API（轮询 tail 起步，够 L0）｜多观测者广播（再开进程各看各的）｜UI 精修（纯文本即可）｜尾行「半行 vs 损坏」二义性（一律按半行等下轮，损坏直致尾部永远不上屏——MVP 接受此代价）
