# intent：my_coding_agent Phase 1——最小 harness 闭环

- 问题：coding agent 四部曲 24 篇研究之后，缺一个「每一行都兜得住」的自研 harness——把研究沉淀成作品集主打项目（实习面试用），全程训练三层核心能力（能读懂/能判断/能修正）。
- 用户/场景：面试官挑任意一行问「为什么这么写」都有答案；自己用终端跑单轮编码任务。
- 输入 → 输出：
  - 输入：终端一句话任务 + GLM API（OpenAI 兼容方言：`/chat/completions` + `tools` + `tool_calls`；base_url / model / key 全走环境变量 `GLM_BASE_URL` / `GLM_MODEL` / `GLM_API_KEY`）
  - 输出：最终文本回答回屏；每次工具调用与结果可见（过程回屏）
- 该拦什么（反例）：
  1. 模型开了注册表里没有的工具名 → 不执行，错误当工具结果回灌模型（不静默、不崩进程）
  2. 工具执行抛错（如读不存在的文件）→ 捕获，错误文本回灌模型继续决策（不崩进程）
  3. 循环超过 max-steps 硬上限（默认 20）→ 强制收工并声明截断
  4. 启动时缺 `GLM_API_KEY` → fail-loud 拒绝启动
- 该放什么（正常场景）：一句话 → 0~N 圈「工单 → 执行 → 结果回灌」→ 最终回答收工
- 验收标准（≤5 条，每条可验证）：
  1. `npm run dev "列出当前目录下所有 .ts 文件"` → ≥1 圈工具调用、结果正确回屏
  2. `npm run dev "1+1 等于几"` → 零工具调用，直接文本回答
  3. 两步任务（读某文件→统计行数）→ ≥2 圈后正常收工
  4. 故意给拼错的工具名任务 → 错误可见、进程不崩
  5. max-steps 临时调成 2 跑复杂任务 → 出现截断声明，不无限转
- 状态：已确认（2026-11-15 用户点将 + 想法池定稿 + G0 过闸 + 模型改选 GLM）
