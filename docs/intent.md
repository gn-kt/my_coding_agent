# intent：my_coding_agent Phase 3+ 想法#6——模型能力识别两段式（先验分级 + 实测复核）

- 问题：harness 对模型盲配——GLM_MODEL 换个名字就换进来一个未知生物：支不支持工具调用、压缩依赖的 usage 账单回不回传，只有跑了炸了才知道。想法 #6 定稿：第一段权威档案**零 token** 先验定级；第二段实测探针复核本环境真能力（榜单分是「模型×脚手架」联合分，判不出自己 harness 里的真水平）。三原则：**硬能力可门禁、软质量只建议、绝不静默降级**。
- 用户/场景：换模型/换供应商前跑 `--check` 看两段式分级报告；日常跑任务与批量实测零开销不受影响。
- 输入 → 输出：
  - 输入：`npm run dev -- --check`（读 .env 的 GLM_MODEL / GLM_BASE_URL / GLM_API_KEY）
  - 输出：两段报告上屏——【第一段·先验】内置档案硬规格判级（工具调用支持/上下文窗口/输出上限）+ 基准分 ⚠️ 建议行（BFCL/SWE-bench，只建议不拦）；【第二段·实测】工具调用探针（发菜单看开单）+ usage 探针（压缩的前置条件）；exit 0 = 可用 / 1 = 硬门禁不过
- 该拦什么（反例）：
  1. 档案明说「不支持工具调用」的模型——先验直接 ❌，不进实测（门禁拦事实：必然干不成活）
  2. 未知模型不得编档案硬判——标「无先验档案」，实测照跑（绝不静默降级 = 未知要明说）
  3. 软分数不得当门禁——BFCL/SWE-bench 低分只出 ⚠️ 建议行（建议管程度）
  4. 探针失败不得静默——❌ 如实上屏（fail-loud）
  5. `--check` 零副作用——不建会话文件、不动 one-shot / `-i` / `--resume` 三路径
- 该放什么（正常场景）：已知模型硬规格全过 + 探针全过 → ✅ 可用；未知模型实测全过 → ✅ 可用（报告注明先验缺席）
- 验收标准（5 条，每条可验证）：
  1. 先验零网络零 token：判级是纯函数（单测断言，不发任何请求）
  2. 两探针各 1 次请求，判据同一把刀：`tool_calls` 非空 = 会调 / `usage` 字段在 = 账单回传（verdict 纯函数单测）
  3. 硬门禁：档案「不支持工具调用」模型 → `--check` ❌ exit 1；软建议只 ⚠️ 不拦（单测）
  4. 未知模型：先验标「无档案」，实测照跑，报告注明（单测）
  5. 回归：34+新 单测全绿 + 原三路径不炸；`--check` 不碰会话
- 范围外（明码标价）：context window 实测探针（真发大上下文太贵——先验规格 + usage 账单间接校验顶上）｜启动自动门禁（每跑任务先打 API，拖批量，2026-11-27 用户裁定 `--check` 手动）｜档案联网自动更新（手维护常量表）｜非 OpenAI 兼容方言的探测（薄 seam 现状只通兼容方言）
