# intent：my_coding_agent Phase 3——解释树（想法 #7）

- 问题：任务跑中/跑完，用户对模型提到的概念不懂，只能跳出会话另开窗口查；在线性会话里直接追问，解释全文会挤爆主线上下文、任务语境越漂越远。想法 #7 的解法：解释做成会话树上的**侧枝**——层层下钻、随时回主线，侧枝摘要成注脚，主线语境零污染。pi 的「原地分叉 + branch_summary」两个机制落地，面试可讲「树+投影的第二种用法」。
- 用户/场景：自己终端跑任务；遇到不懂的术语当场 `/explain` 下钻追问；`/back` 复述检验后回主线继续任务；`/tree` 随时看树形。
- 输入 → 输出：
  - 输入：新增 `--interactive` REPL（普通输入=主线任务；`/explain <术语>` 开侧枝；侧枝内普通输入=追问下钻；`/back` 复述检验+回主线；`/tree` 打印树；`/exit` 退出）
  - 输出：同文件内真分叉的会话树（侧枝挂分叉点下）+ `branch_summary` 注脚条目；one-shot / `--list` / `--resume` 全保留不动
- 该拦什么（反例）：
  1. 坏树 fail-loud：parentId 悬空 / 重复 id / 第二个根 → 拒载（Phase 2 反例 4 的树形升级；「父必先于子」的追加写格式让环天然不可能，无需额外检测）
  2. 侧枝全文不得进主线上下文——只以 branch_summary 注脚出现（防上下文爆炸与主线漂移，想法 #7 原句）
  3. 复述检验不通过不得静默回主线——注脚必须带「待巩固」标记（防假懂）
  4. 侧枝物理禁开工具单——侧枝 chat 不发 tools 字段（同软着陆手法：物理禁开，不是 prompt 建议性约束）
  5. 已解释术语再 `/explain` → 去重：指引已有注脚，不重讲
- 该放什么（正常场景）：REPL 任务 → `/explain` 下钻 ≥2 层 → `/back` 复述检验 → 注脚回主线 → 继续任务；投影始终 = 活跃路径（当前叶子沿 parentId 走到根）
- 验收标准（5 条，每条可验证）：
  1. `/explain` 下钻 ≥2 层后 `/tree` 打印出真分支（侧枝挂分叉点下）；`--interactive <id>` 重开树形还原
  2. 侧枝内模型接得住追问语境（投影 = 主线前史 + 解释链），且侧枝条目零 tool_calls
  3. `/back` 复述检验通过 → branch_summary 进树挂主线叶子下；回主线后投影含注脚、不含侧枝全文
  4. 同一术语二次 `/explain` 被去重拒绝，指引已有注脚
  5. 回归：Phase 1/2 全量验收路径不炸（one-shot / `--list` / `--resume` / 压缩 / 软着陆）+ 坏树文件 fail-loud 拒载
- 范围外（明码标价）：fork 文件级协作（想法 #8 另案）｜侧枝内压缩（侧枝是短解释对话，爆窗属超范围）｜侧枝内再分叉（侧枝内 `/explain` 当普通追问）｜UI 树导航（`/tree` 只打印文本）
